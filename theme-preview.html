原始需求.md

需求摘要

本案採用 方案 A：API 統一輸出商品前台狀態。後端根據既有「產品標籤」、 原因分類、EventDate、RemindText 快速到貨類別等資料， 統一判斷商品在前台應呈現的狀態。Web 與 App 不各自推導規則，只負責依 API 回傳的狀態物件顯示畫面。

核心目標是讓「產地直送」商品在不可購買時，也能清楚告訴消費者原因： 「產季結束」、「產季未到」、「氣候因素暫停接單」、「供貨不足，暫停接單」或「本商品已停止販售」。

統一狀態物件建議

API 建議回傳一組前台專用狀態物件，避免 Web / App 各自解讀標籤資料。

欄位 型別 用途
status string 前台狀態代碼，例如 seasonEnded、seasonNotStarted、weatherPaused、supplyPaused、discontinued
labelText string 商品圖蓋圖文字
buttonText string 商品頁主要按鈕文字
canAddToCart bool 是否可加入購物車
showInList bool 是否出現在分類 / 一般列表
showInSearch bool 是否可被站內搜尋找到
showProductPage bool 商品頁是否可正常開啟
seasonText string / null 顯示「產季未到」時帶出的預計產期，來源為 RemindText
reasonType string / null 原始原因分類，供 debug / 後台查核使用
reasonName string / null 原始原因名稱，供 debug / 後台查核使用

狀態判斷順序

狀態應由 API 以固定優先序決定，前端不再用庫存、標籤、分類自行推論。

  1. 若商品已設定永久停售，回傳 discontinued，列表與搜尋皆不顯示。
  2. 若商品有產季結束標籤，回傳 seasonEnded，商品頁可開啟但不可加入購物車。
  3. 若商品尚未到產季，回傳 seasonNotStarted，並帶出預計可購買月份。
  4. 若商品因氣候或供貨暫停，回傳 weatherPaused 或 supplyPaused。
  5. 若以上條件皆不符合，依既有可購買規則回傳 available。

前台文案規格

狀態 商品圖標籤 商品頁按鈕 補充說明
seasonEnded 產季結束 暫停販售 保留商品頁，避免消費者從外部連結進來時看不到資訊。
seasonNotStarted 產季未到 到貨提醒我 若有 seasonText，可顯示「預計 12 月開採」。
weatherPaused 暫停接單 到貨提醒我 用於颱風、豪雨、低溫等不可控因素。
supplyPaused 暫停接單 到貨提醒我 用於採收量不足、產地臨時調度等供貨因素。

待確認問題

  • 「永久停售」是否仍允許既有收藏、訂單紀錄連回商品頁？
  • 「產季未到」是否需要在分類列表中排序往後，避免壓過現貨商品？
  • 到貨提醒是否需要區分「產季提醒」與「一般補貨提醒」兩種通知文案？
  • GoX 後台是否要新增一欄顯示 API 判斷後的最終前台狀態？
